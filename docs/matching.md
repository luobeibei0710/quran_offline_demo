# 经文匹配与指标

本文说明「一段转写文本如何被定位到全经第几章第几节」，
以及界面上的覆盖率 / 解释比例 / F1 / 严格 WER 到底是什么口径。
实现位于 `lib/broadcast/application/quran_match_service.dart`（广播侧裁决）与
`lib/quran_offline/quran_matcher.dart`（召回 + 精排，两库共用）。

## 1. 问题定义与约束

输入是一段**已确认的语音片段**（不是滑窗、不是逐帧）：片段由断句状态机切出，
可以覆盖半节、一节、跨若干节，也可以是库外内容（求护词、解说、其它章节）。

因此匹配不能简化成「分类」或「找到最相似经文」，必须同时满足：

| 要求 | 落实方式 |
|------|----------|
| 全经 6236 节里定位 | 文本召回 + CTC 约束精排，候选空间是整库 |
| 允许半节 | 结果以节范围表达，不补全未听到的内容 |
| 允许跨节连读 | 一个片段可对应多个节引用，不只取跨度首节 |
| 允许真实复读 | 同一节在不同时间诵读产生不同片段与记录 |
| 相同开头要允许歧义 | 太斯米 / 极短节 / 重复节不能被硬选，低可信时标「候选」 |
| 库外内容如实拒识 | 检索不到就返回未匹配，保留真实转写，不返回「最相似经文」 |

## 2. 流水线

```
ASR 转写（归一化）
   ↓
① 召回：分词倒排 + 覆盖率 / 长度匹配度打分 → topK 个种子节
   ↓
② 扩展：以种子节为起点生成 1..maxSpan 节的跨度候选
   ↓
③ CTC 精排：对每个候选算前向后向对数似然，按**帧数**归一化 + 跨度惩罚
   ↓
④ 裁决：按「转写被候选解释的比例」(precision) 分带排序，同带内比 CTC 排序分
   ↓
⑤ 判定：可信度 + 覆盖率门槛 → confirmed / partial / candidate / unmatched
   ↓
⑥ 指标：词级对齐（Needleman–Wunsch）算 P / R / F1，另算严格 WER
```

### 2.1 为什么打分按帧而不是按 token

`CtcScorer` 早期以 token 数归一化：token 越多分母越大，
多节连读的候选会**系统性占优**，而设备端与 x86 的浮点差异会把这个偏好放大成次序翻转
（实测 `112:1` 在 ARM 上被判成 `112:1-3`，而转写文本完全正确）。

现改为**按帧数归一化**：同一段音频的帧数是常数，所有候选同口径比较。
跨度惩罚随之重新标定。

### 2.2 为什么还要一次「候选二次裁决」

按帧归一化解决的是「token 多的占便宜」，但它仍然**只衡量候选能否解释音频，
不衡量音频能否被候选解释**。这会造成一个具体错误：

- 音频：`بسم الله الرحمن الرحيم قل هو الله احد`（`112:1`，含章首太斯米）
- 候选 A：`1:1` —— 太斯米本身，5 个 token，全部有强声学证据
- 候选 B：`112:1` —— 太斯米 + 正文，10 个 token

A 的按帧分数更优（它只用到高概率的前 5 个位置），于是纯太斯米节会抢走所有
以相同开头起诵的长片段。

因此在 CTC 精排之后增加一层裁决：**先按「转写被候选解释的比例」(precision) 分带，
同带内再比 CTC 排序分**。这同时满足了「相同开头、太斯米、极短节要允许歧义状态」的要求。

### 2.3 三个由真实音频暴露的问题

用真实全经诵读音频在主机上跑端到端时暴露出三个连锁缺陷，均已修复，
记录在此以便回归（现场与数据见 §6.1）：

| # | 现象 | 根因 | 处置 |
|---|------|------|------|
| 1 | 开端章窗口转写覆盖 6 节，匹配只给 4 节，解释比例被压到 0.60 | `maxSpan = 4`；此前在王权章标定（30 s ≈ 2 节），而全经有大量极短节（开端章 2–9 词/节），30 s 可跨 5–6 节 | token 表按 `maxSpan = 8` 重建（46,752 条跨度），配置同步取 8 |
| 2 | 提高跨度上限后仍无改善 | 候选池按 CTC 排序分截断，而按帧归一化的分数**系统性偏好极短候选**（正确候选 `1:3-7` 排到 130 名开外） | `runnerUpLimit` 放大到 1024（即不截断），并在裁决前按「参考词数与转写词数的接近度」重排，只对前 192 个做词级对齐 |
| 3 | 上面两处修完后跨节候选仍选不出来 | CTC 打分要求候选满足 `token 数 × 2 + 1 ≤ 帧数`；转写按声学暂停切成 3–10 s 子窗，子窗帧数只够短候选 | 转写仍分段（保 ASR 质量），**匹配改用整段音频的原生证据**（见 [架构 §3](architecture.md)） |

修复前后对比（开端章，主机直连音频）：

| 窗口 | 修复前 | 修复后 |
|------|--------|--------|
| 5.5 s | `1:1–1:4`，解释 0.60，F1 0.727 | **`1:1–1:6`，解释 0.95，F1 0.950** |
| 11.0 s | `1:1–1:4`，F1 0.571 | **`1:1–1:7`（全章）**，F1 0.725 |
| 16.4 s | `1:5, 1:6`，解释 0.32，F1 0.483 | **`1:3–1:7`**，解释 0.84，F1 0.860 |

## 3. 阈值常量

`BroadcastMatchConfig` 的默认值（`lib/broadcast/application/quran_match_service.dart`）：

| 参数 | 默认 | 作用 |
|------|------|------|
| `topK` | 32 | 参与 CTC 精排的召回候选数 |
| `maxSpan` | 8 | 最大连读跨度（节） |
| `spanPenalty` | 0.1 | 排序分里的跨度惩罚 |
| `minPrecision` | 0.6 | 转写词被候选解释的比例下限（达标候选门槛） |
| `minCoverage` | 0.5 | 候选原文被覆盖比例下限（确认门槛） |
| `minConfidence` | 0.35 | 综合可信度下限（确认门槛） |
| `minContentWords` | 2 | 至少命中的内容词数 |
| `precisionBand` | 0.05 | 裁决时解释比例的分带宽度（避免浮点抖动） |
| `precisionWeight` | 0.7 | 可信度中解释比例的权重 |
| `marginWeight` | 0.3 | 可信度中候选差距的权重 |
| `minFallbackCoverage` | 0.4 | 候选回退所需最低覆盖率 |
| `minFallbackTextScore` | 0.35 | 候选回退所需最低文本得分 |
| `minFallbackPrecision` | 0.3 | 候选回退所需最低解释比例（防极短节误回退） |
| `runnerUpLimit` | 1024 | 参与上层裁决的候选数上限（1024 = 不截断） |
| `candidateShortlist` | 192 | 裁决阶段最多做多少次词级对齐 |
| `recallLengthFitWeight` | 0 | 召回打分里「长度匹配度」的权重（0 = 旧库语义） |
| `recallBalance` | 0.5 | 召回打分里「候选被覆盖比例」的权重 |

补充说明：

- **`maxSpan` 取 8 而不是 4**：全经有 553 个 ≤3 词的极短节，30 秒片段可跨 5–6 节；
  取 4 会让匹配范围明显窄于转写内容；
- **`runnerUpLimit` 取 1024**：候选总数上限就是 `topK × maxSpan = 32 × 8 = 256`
  （也即全部候选），不截断的代价只是裁决阶段多做几百次词级对齐（实测 200–500 ms）；
- **`recallBalance` 取 0.5**：只算「转写被候选覆盖的比例」时，
  跨多节的转写会让每个正确单节最多只贡献 1/N 的分，正确节与「恰好含常见词的无关节」无法区分；
  补上「候选被转写覆盖的比例」后，只有真正被念到的节才会浮上来；
- **`recallLengthFitWeight` 保留但取 0**：全经有 553 个 ≤3 词的极短节，
  其中多个节文本完全重复（例如 `ويل يومئذ للمكذبين` 出现在 11 个节）。
  按覆盖率召回时极短节会垄断候选池，该参数用于抑制长度明显偏短的候选；
  广播侧当前取 0，靠裁决层的 `minFallbackPrecision` 与「按词数接近度重排」达到同样效果。
  **完全同文的节无法从音频区分，这是物理限制**，只能通过低可信度表达为「候选」而不是硬选一个。

> 这些阈值是**标定起点**，不是已验收常数：上游 token 分数未公开，
> 广播 token 表由本仓库用确定性分词生成，排序分绝对值口径与旧库不同。
> 标定范围与边界见 §6。

## 4. 状态判据

| 状态 | 判据 | 落地含义 |
|------|------|----------|
| `confirmed` | 存在达标候选（`precision ≥ 0.6` 且 `matchCount + nearCount ≥ 2`），且 `coverage ≥ 0.5`、`confidence ≥ 0.35`，且覆盖的节都是完整节 | 已确认，给出完整节引用 |
| `partial` | 同上，但覆盖范围不是完整节 | 部分节，不补全未听到的内容 |
| `candidate` | 达标候选存在但未过确认门槛；或只有回退候选（`coverage ≥ 0.4`、`precision ≥ 0.3`、`textScore ≥ 0.35`） | 展示候选供参考，**回退候选永不升级为 confirmed** |
| `unmatched` | 无候选 / 只识别到章首太斯米 / 没有候选能解释转写 / 没有对齐上的节 | 保留真实转写，不返回「最相似经文」 |

可信度计算：

```
margin      = 最佳候选排序分 − 其它引用中的最近排序分
scale       = |最佳排序分| × 0.15                     // 相对差距基准
marginScore = clamp(margin / scale, 0, 1)
confidence  = clamp(0.7 × precision + 0.3 × marginScore, 0, 1)
```

`confidence` 是**启发式提示值**：完美匹配与长窗口下会饱和到 1.00，不参与判定。

拒识理由会写入 `matcher_evidence` 并可在记录详情页的「开发诊断」区查看，
例如「仅识别到章首太斯米」「全经语料内没有候选」「没有任何候选能解释…」。

## 5. 指标口径

### 5.1 词级对齐（`word_alignment.dart`）

用 Needleman–Wunsch 动态规划对齐「候选原文」与「转写文本」，
缺词/多词各扣 `gapPenalty = 0.5`；词相似度取归一化后的字符级 Levenshtein 比例。

一旦漏词、多词，按下标硬比会让后面所有词全部判错，动态规划可以避免。

| 状态 | 条件 | 颜色 |
|------|------|------|
| 一致 | 相似度 ≥ `matchThreshold = 0.80` | 绿 |
| 近似 | `nearThreshold = 0.50` ≤ 相似度 < 0.80 | 黄 |
| 错配 | 相似度 < 0.50 | 红 |
| 缺失 | 原文有、转写无 | 蓝灰 |
| 多余 | 转写有、原文无 | 橙 |

```
覆盖率 R = (一致 + 0.5 × 近似) / 原文词数
准确率 P = (一致 + 0.5 × 近似) / 转写词数
F1      = 2PR / (P + R)
```

结论分档：`优秀 ≥ 0.90`、`良好 ≥ 0.75`、`一般 ≥ 0.55`、`较差 < 0.55`。

口径说明：

- **近似词按半分计入**：阿拉伯语形近词（如 `الرحمن` / `الرحيم`）出错时通常读音相近，
  直接算错会低估可懂度、算对又会高估，故取半分；
- **覆盖率与准确率必须同时看**：只念了一小段时覆盖率低但准确率可能很高，
  乱识别时准确率低，F1 把两者拉平；
- **这里的 F1 是「转写与候选原文的一致性」，不是独立准确率保证。**

### 5.2 严格词错误率（`word_error_rate.dart`）

归一化后按**精确词**统计替换 / 缺失 / 多余：

```
WER = (S + D + I) / 原文词数
```

与 F1 的关键区别：**近似词在这里按错处理**，WER 允许超过 100% 且不截断美化。
因此不能把「容错 F1 ≥ 0.95」写成「严格词准确率 ≥ 95%」。

### 5.3 无可信参考时的处理

没有可对齐的参考原文时，指标为 `null`，界面显示**「不可用」**而不是 0 分。

### 6.2 参数标定

在真实整章音频（王权章 455 s，25 s 窗口 / 8 s 步长，54 个有效窗口）上做过灵敏度检验：

| 参数 | 结果 |
|------|------|
| `spanPenalty` | 0 / 0.02 / 0.05 / 0.1 / 0.2 **五档结果完全相同** |

原因是候选裁决以**解释比例分带优先**，排序分（含跨度惩罚）只在同一带内参与比较，
而不同跨度的解释比例差异通常跨带。因此 `spanPenalty` 保持 `0.1`
（与旧库同值，便于两库对照）。

`maxSpan` 的取值不来自这一轮灵敏度检验（25 s 窗口最多用到 3 节，4 与 6 无差异），
而是由 §2.3 暴露的「跨度不足」问题与 §6.1 的端到端证据确定：**取 8**。

**标定边界**：以上都是主机直接解码音频的结果，
**不等于真机外放拾音质量**，也不是人工标注的节级 ground truth。

## 7. 未验证与已知边界

1. **没有人工标注的节级 ground truth**：除王权章 3 个窗口外，
   其余只验证到「章正确」，节位正确性是间接推断；
2. **标定素材单一**：单个诵读者（Alafasy）+ 主机直连音频；
   多诵读者、多距离、多底噪条件下的确认与拒识行为没有对照数据；
3. **重复节的歧义行为未专门设计用例**：至仁主章有 31 次重复节，
   本轮三个窗口都落在唯一节上，没有验证歧义场景的状态表达；
4. **预览路径未降配**：实测预览匹配 P95 1696 ms（n=635）已超过 1 s 的预览周期，
   理论上预览应使用更小的 `topK` / `maxSpan`，尚未验证必要性；
5. **未匹配的分层归因缺失**：预览层的未匹配片段中，多少是库外内容
   （求护词、解说、其它章节）、多少是拾音质量导致，尚未分开统计；
6. **真机延迟只有单轮样本**：P50/P95 来自首轮 33 分钟播放，
   未在其它设备或其它拾音条件下复测，也尚未确定延迟验收阈值。
