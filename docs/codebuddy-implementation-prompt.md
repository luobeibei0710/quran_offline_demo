## 四、实际使用流程

另一设备播放经文广播，手机通过麦克风收音，在本机离线完成：

音频采集 → 阿拉伯语ASR转写 → 句段确认 → 新库经文匹配 → 目标语言译文 → 保存记录。

首期前台运行，不加入系统内录、通话录音、后台常驻或云翻译。识别过程中显示实时转写草稿，完成一句后再翻译和保存；不要把每次模型回调都保存成一条历史。

“一句”是有明确音频起止时间的已确认片段，不必等同一节经文。支持半节、跨节、同节真实复读和跳章。相同音频片段多次回调只更新同一记录；同一经文在不同时间真实复读必须生成不同记录。

其他章节或广播解说不属于新库覆盖范围：保留真实ASR转写，显示未匹配，不要返回任意最相似经文。

- 使用SQLite/Drift或与现有架构兼容的持久方案，保存独立的转写、原文和译文快照，不靠内存列表。
- 记录包含recordId、稳定序号、sessionId、utteranceId、revision、音频起止时间、语言、corpusId/version、匹配范围、状态、来源和各阶段耗时。
- 比对显示Precision、覆盖率Recall、F1、严格WER、S/D/I及逐词差异，明确这些是“转写与候选原文一致性”，不是独立准确率保证。
- 没有可信参考时指标为null，不显示0分或伪造高分。WER允许超过100%，不得截断美化。
- 记录与翻译任务事务保存；翻译异步处理，失败不丢记录，重启可恢复任务。
- 迟到译文只能更新对应recordId/revision/目标语言，不能覆盖当前新句。删除后迟到结果不能复活记录。
- 缓存包含输入hash、corpusId/version、目标语言、引擎/译本版本及预处理版本。
